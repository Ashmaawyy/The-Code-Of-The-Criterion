Why This Budget Is Worth Considering

Al-Furqan already has the correct safety architecture: source integrity, formal checks, provider abstraction, and audit layers. The model should not become the authority. It should become a better disciplined mediator between user claims, the knowledge base, Z3-backed gates, and human review.

Expected gains

  • More reliable execution of the four Criterion gates in the right order.
  • Lower prompt fragility for Arabic/English scholarly reasoning workflows.
  • Better structured outputs for claims, evidences, contradictions, and uncertainty.
  • Reduced hallucinated citations when trained against explicit negative examples.

What fine-tuning will not solve

  • It will not replace the Quran/Hadith/Fiqh/Tafsir knowledge base.
  • It will not replace Z3 or source-integrity checks.
  • It will not guarantee theological correctness without curated data and review.
  • It will not remove the need for human-in-the-loop validation on sensitive claims.

Model Strategy

Candidate Role in pilot Reason Decision rule
Qwen3-8B Primary first model 8.2B parameters, Apache-2.0, multilingual, supports thinking and non-thinking mode, cheap enough for iteration. Train first. Continue only if it beats prompt baseline on gate compliance and citation discipline.
Qwen3.6-27B Larger-model validation 27B open-weight model with stronger agentic and long-context positioning, but needs larger GPU memory. Run only after 8B pipeline succeeds or fails in a way likely solved by scale.
Qwen3-32B Alternative larger candidate 32.8B open model, text-generation focused, similar hardware class to the 27B pilot. Compare against 27B if text-only behavior is preferred over multimodal architecture.

Note on naming: the earlier phrase "Qwen 3.7" is treated here as "Qwen 3.x family." This proposal uses currently visible official/open candidates: Qwen3-8B, Qwen3.6-27B, and Qwen3-32B.

Training Approach

Method

  • Supervised fine-tuning with LoRA/QLoRA adapters, not full fine-tuning.
  • Use TRL or Unsloth for memory-efficient training.
  • Keep base model frozen; train small adapter weights that can be merged or served separately.
  • Push artifacts to Hugging Face Hub or internal model storage after each accepted run.

Dataset scope

  • 1,500-5,000 curated training examples for the first pilot.
  • 300-500 held-out evaluation cases.
  • Include positive and negative examples: correct gate traces, bad citations, unsupported claims, contradictory evidence, and refusal/uncertainty cases.
  • Do not train on unverified religious claims as if they were ground truth.

Six-Week Execution Plan

Week 1 Build dataset schema, eval harness, and baseline prompt-only results.
Week 2 Run Qwen3-8B smoke tests and fix data formatting failures before serious GPU spend.
Week 3 Train Qwen3-8B candidate adapters and evaluate against held-out gate tests.
Week 4 Run Qwen3.6-27B or Qwen3-32B comparison if the 8B pipeline passes.
Week 5 Perform red-team evals: false citations, unsupported claims, contradictions, and refusal cases.
Week 6 Deliver model card, evaluation report, recommendation, and production budget decision.

Go / No-Go Criteria

Proceed if

  • Qwen3-8B adapter improves gate-order compliance by at least 15% over prompt-only baseline.
  • Source-citation hallucination rate decreases or remains below the current baseline.
  • Structured output validity improves enough to reduce post-processing exceptions.
  • The 27B/32B candidate shows a meaningful gain on difficult reasoning cases before expanded spend.

Stop if

  • The adapter fabricates sources, weakens source-integrity behavior, or bypasses tool verification.
  • The 8B model does not beat the prompt-only baseline after data cleanup.
  • 27B/32B gains are marginal compared with 8B but add deployment cost and latency.
  • Data curation becomes the bottleneck before model size becomes the bottleneck.

Risks and Controls

Risk Impact Control
Model learns confident theological style without evidence discipline. High Train on explicit refusal, uncertainty, and source-integrity examples; evaluate hallucinated citations separately.
Training data bakes in unsupported or weak claims. High Curate data through the existing source-integrity process; mark weak evidence as weak, not true.
27B/32B model costs more to serve than the benefit justifies. Medium Require 8B baseline first; approve 27B only when evals justify scale.
Cloud job failures waste spend. Medium Run CPU validation first, small smoke tests second, and checkpoint/push artifacts on every serious run.
Scope drift toward full training or production hosting. Medium Keep this as a capped pilot. Production inference requires a separate proposal.

Recommendation

Approve Scenario B: $2,500 maximum spend. It gives the project enough room to prove the practical value of fine-tuning without committing to production infrastructure. Spend should be released in gates: first $750 for the 8B feasibility stage, then the remaining allowance only if the baseline evals justify a larger-model comparison.

The strongest management position is not "buy the biggest model." It is: fund a disciplined experiment, protect source integrity, measure the result, and scale only if the evidence says model size is the limiting factor.
